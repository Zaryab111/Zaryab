Empirical software engineering

Do bug fixes come with tests?

I mined 12,537 commits from 15 Python projects. The fix-keyword rule was only 30% precise on a labelled sample, and the first result (fixes touch tests more often, 50.0% vs 46.2%) disappeared under a fair comparison (41.7% vs 38.8%, p = 0.059).

Limits: single labeller, 15 popular projects, recall of the fix label not measured.

REST API design

rest-api-lint

A checker for REST API design rules, run on 200 public OpenAPI specifications. Precision was 39% on the first 100 flagged issues; after fixing the noisy rules it was 89% on a fresh sample of 100.

Limits: the same person tuned the rules and labelled both samples; recall unknown; JSON specifications only.

Static analysis

Logging practice in Python projects

An ast-based study of 21 projects: applications log about 8 times more than libraries (2.24 vs 0.28 calls per 1,000 lines, p = 0.002).

Limits: hand-picked samples, receiver-name matching, latest snapshot only.

Final-year project, industrial R&D, two-person team

Eldercare: fall detection platform

A camera-based system that detects falls in older people living alone and alerts caregivers. Supervisor: Ms. Asmara Safder.

  • My part: Flutter web and Android app, FastAPI backend, self-hosted PostgreSQL and Redis, WebSocket and Firebase push alerts, Docker deployment, integration testing, and most of the project report. We moved from a managed backend to self-hosting so that sensitive health data stayed under our control.
  • Team result: the detection model, MAGnet, was built and trained by my teammate Muhammad Hasaan. It reached 98.2% accuracy and 99.78% ROC AUC on 38,674 windows from two public datasets (NTU RGB+D 120, FallVision). Falls only; seizure detection is future work.
  • A research manuscript based on the project is in its final stages.

Limits: public datasets only; live use on many cameras needs a strong GPU; alerts not tested with real caregivers.

About

I am based in Lahore and studied computer science at COMSATS University Islamabad, graduating in 2026. My final-year project, Eldercare, was an industrial research and development project in a team of two: a camera-based system that detects falls in older people living alone and alerts their caregivers. I built everything around the detection model: the web and mobile app, the backend, the alerting and the deployment. We chose to self-host the database so that health data stayed under our control. My teammate built the detection model, which reached 98.2% accuracy on public datasets.

Since July 2026 I have worked as an AI engineer at Applicon Soft, building with large language models: a workflow that generates tests and database migrations, a speech-enabled chatbot, and an agentic retrieval-augmented generation setup with guardrails.

Doing both left me with a question I want to study properly: how do we know these systems work? That is why I started small empirical projects on software repositories. The most useful lesson so far came from the first one. My first result looked clear, then I found that my own filter was producing it, and a fair comparison made the difference disappear. I want to do more of that careful checking, in software engineering for AI, LLMs for code and cyber security.

Research is where I want to take this next, through a master's programme or a research internship. Alongside my studies I have worked as a freelance content writer and social media manager since 2020, writing for psychiatrists and therapists and running content for clients, so I am used to explaining technical and sensitive material to people who are not experts.
